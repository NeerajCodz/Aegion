## Priority 1: Critical Bug Fixes (Security & Correctness)

### P1.1 Error String Comparison Anti-Pattern
**Severity**: HIGH (Unreliable Error Handling)
**Issue**: Multiple places compare error messages as strings instead of using `errors.Is()` or sentinel errors
**Files**:
- `modules/oauth2/store/*.go` - Comparing `err.Error()` strings for flow validation
- `modules/password/store/*.go` - Hash validation error checks
- `modules/social/service/*.go` - Provider error handling

**Impact**: 
- Error handling brittle and fails if error message changes
- Makes refactoring risky
- Harder to localize/translate errors in future

**Recommended Fix**:
- Define sentinel errors (e.g., `ErrInvalidPassword`, `ErrUserNotFound`)
- Replace `err.Error() == "some string"` with `errors.Is(err, ErrInvalidPassword)`
- Create error types for provider-specific failures in social module

**Effort**: Medium | **Risk**: Low

---

### P1.2 Missing nil Pointer Checks in Provider Chain
**Severity**: MEDIUM (Potential Panic)
**Issue**: Social providers don't validate profile data before accessing fields
**File**: `modules/social/providers/*.go` (Apple, GitHub, Google, Microsoft, Roblox)
**Example Pattern**:
```go
providerUser := resp.User  // No nil check
email := providerUser.Email  // Could panic if resp.User is nil
```

**Impact**: Provider connection failures could crash goroutines instead of returning errors

**Recommended Fix**:
- Add nil checks after unmarshaling provider responses
- Return descriptive errors instead of panicking
- Add integration tests with mock provider responses

**Effort**: Low | **Risk**: Low

---

### P1.3 Resource Cleanup in Error Paths
**Severity**: MEDIUM (Resource Leak)
**Issue**: Some gRPC server initialization doesn't properly close listener on error
**File**: `modules/*/cmd/server/main.go`

**Impact**: Failed server startup could leak resources

**Recommended Fix**:
- Ensure listener.Close() called on all error paths
- Use defer for cleanup

**Effort**: Low | **Risk**: Low
